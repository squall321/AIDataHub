01 · Executive Summary

두 질문에 대한 한 장 요약

모든 수집 경로는 하나의 코어(write_record())로 수렴하고, 모든 검색은 하나의 코어(search_svc)로 수렴한다. 그 사이를 잇는 것이 "공통 포맷"이다.

Q1. 어떻게 모을 것인가

  • 원본 파일(docx·xlsx·pptx·md·pdf) → 표준 JSON으로 변환
  • 4개 진입점(REST 벌크 / 파일업로드 / CLI 배치 / MCP)이 모두 RecordIn → write_record로 수렴
  • 메타데이터는 유사데이터 기반 자동제안(doc_type·tags·graph_type) + 사람 확정(team·group)으로 이원화
  • content_hash 기반 멱등 UPSERT로 중복 흡수

Q2. 어떻게 검색할 것인가

  • 태그 / 전문(FTS) / 의미(벡터) / 하이브리드(RRF) / 유사도 / 에이전트-스코프
  • 의미검색은 pgvector HNSW 코사인, 하이브리드는 RRF k=60으로 어휘+의미 융합
  • 선택적 cross-encoder 리랭킹(bge-reranker-v2-m3)
  • 에이전트 persona가 retrieval_config로 검색 범위·임계·가중을 결정

연결고리 — 공통 포맷

  • 1회 정의: doc_type(권장 섹션·임베딩 정책) + agent(검색 레시피)를 MCP로 만든다
  • 이후 용이: 같은 종류 데이터는 data_type/team/group/year만 주면 ID 자동채번·동일 임베딩 정책 상속
  • 유사도 제안이 "비슷한 데이터를 비슷하게" 분류해 상호검색성 유지
설계 철학. 사람이 화면에서 보기 위한 포맷(PPT·Excel)을 기계가 처리하는 포맷(구조화 JSON + 벡터)으로 바꾸는 것이 목표다. 변환·분류·임베딩의 반복 비용을 공통 포맷을 먼저 세워 상수화하고, 개별 레코드 추가는 그 위에 얹기만 한다. ai_data_strategy.md §2 · mcp_runtime.py:45-78(_INSTRUCTIONS)

07 · Format-Once, Add-Easily

공통 포맷을 한 번 정의하면, 이후 추가는 쉬워진다

검색에 필요한 공통 부분(스키마·분류·검색레시피)을 MCP로 입력해 포맷을 형성한다. 형성 후 개별 레코드 추가는 최소 입력으로 기존 포맷에 슬롯팅된다.

(a) 한 번 DEFINE 되는 것 — 재사용 "포맷"

  • doc_type = 의미분류 코드 + expected_sections(권장 골격) + mode(임베딩 정책). create_doc_type → doc_type_svc.py:28
  • agent = 검색 페르소나: system_prompt + retrieval_config + required_doc_type/tags. create_agent → mcp_write_svc.py:282
  • 안내 표면: describe_record_schema(필수/권장 필드·enum·예시), describe_data_capability(타입별 shape). ingest_guide_svc.py:39 · discover_svc.py:97
  • Ingest Kit: SYSTEM_PROMPT + SCHEMA.json + self-contained validate.py(enums 하드코딩, 오프라인 반복검증). ingest_kit_svc.py:36
  • Word 템플릿: agent의 required_doc_type+expected_sections를 채운 .docx 생성. template_svc.py:26

(b) 이후 EASY 해지는 것 — 레코드 일관 추가

  • auto_seq 슬롯팅: id 없이 data_type/team/group/year만 주면 다음 seq 채번+format_id → 기존 번호체계에 자동 편입. records.py:724-751
  • 임베딩 정책 상속: 같은 doc_type의 2번째 레코드는 첫 레코드와 동일 mode로 임베딩 여부 자동 결정. db_writer.py:542-570
  • 유사도 제안 순환: 저장 즉시 시그니처 임베딩 → 다음 데이터의 find_similar_data 이웃 풀에 편입. mcp_write_svc.py:203-211
  • 폴더 대량 추가: batch는 team/group/year 한 번만 주고 폴더를 던지면 반복 적재. ingest/batch.py:84-99
  • 부모(campaign) 연결 제안: doc_type 동일이 최강 신호인 결정론적 휴리스틱. parent_suggest_svc.py:55
정직한 검증. 포맷은 강제(hard-reject)가 아니라 권고(warn-only)다. 미등록 doc_type·expected_sections 불일치·required_tags 누락은 모두 로그 경고만 남기고 저장된다(db_writer.py:333-383). 주입 순서(find_similar_data → import) 역시 서버가 강제하지 않고 MCP 지시문으로 클라이언트 LLM에 위임한다. 즉 일관성은 (유사도 제안) + (LLM이 규약을 따른다는 전제)로 달성되며, DB 제약으로 봉인되지 않는다.
